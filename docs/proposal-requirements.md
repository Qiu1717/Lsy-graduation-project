# 生产车间工装夹具配置管理系统 · 开题需求草案

课题全称为《基于 Spring Boot + Vue 的生产车间工装夹具配置管理系统的设计与实现》。本文供开题讨论使用。四项功能和技术栈来自选题说明，具体角色、匹配规则、状态和验收样例是第一版建议，待任务书与导师意见确认。

## 一、系统要解决的问题

一张工单指定了工位和夹具需求。工装管理员需要查到哪些实物适用、现在能否领用、已经分给哪张工单。操作结束后，应能按实物编号查清谁领过、何时归还、何时送修，以及在哪些时间段处于闲置状态。开题报告可用这条业务过程说明课题目标。实际车间的现行做法、耗时和差错率有待调研。

## 二、功能与权限

| 选题要求 | 建议操作 | 可观察的结果 |
| --- | --- | --- |
| 用户与权限 | 系统管理员维护账号并授权；各用户登录后维护个人资料 | 操作员可修改本人的资料；直接调用角色授权接口时，后端拒绝其请求 |
| 夹具、工位与状态维护 | 工装管理员登记型号、适用工位和逐件实物编号，维护工位资料，查询当前位置和状态 | 同型号的两件夹具可以分别处于空闲和维护状态；按编号可查各自记录 |
| 按工单匹配、分配 | 工装管理员登记工单、目标工位、需求型号和件数；系统生成候选清单，管理员确认具体实物 | 同时满足型号、工位兼容和空闲三个条件的实物进入清单；确认成功后被该工单占用 |
| 借还、维护及闲置记录 | 操作员领用已分配给其工单的夹具并登记归还情况；工装管理员处理送修和维修完成 | 归还、送修、修复均可追溯；可按实物查询当前与历史闲置区间 |

建议将“型号适用于哪些工位”和“某件实物当前放在哪里”分别记录。例如夹具放在库房，仍可供适配的工位选用。系统管理员负责授权，工装管理员负责业务配置；首次演示可用三个不同角色账号验证权限。

## 三、第一版匹配与状态规则

1. 工单列明目标工位、型号及数量。对每个需求型号查询适用该工位且当前空闲的实物。同一型号的多件夹具按唯一编号区分。
2. 工装管理员选足所需件数后确认。建议首版采用整单分配，候选不足时显示缺口并保留工单待分配。若车间允许部分领用，应在开发前确定分批分配规则。
3. 确认时由后端再次检查每件夹具并在同一数据库事务中写入分配记录、更新状态。两张工单同时选择同一件夹具时，只允许一方成功；失败方刷新候选清单。
4. 每次状态变更记录实物编号、前后状态、时间、操作人、原因和关联业务记录。已分配但未领用时可以撤销，保留原分配和撤销记录。

| 当前状态 | 业务动作 | 下一状态 |
| --- | --- | --- |
| 空闲 | 确认分配给工单 | 已分配 |
| 已分配 | 登记领用 / 领用前撤销分配 | 已借出 / 空闲 |
| 已借出 | 完好归还 / 损坏归还并登记送修 | 空闲 / 维护中 |
| 空闲 | 登记送修 | 维护中 |
| 维护中 | 维修完成并确认可用 | 空闲 |

实物入账可用或再次进入空闲时，开启闲置区间；下次分配或送修时结束该区间。尚未结束的区间按查询时刻计算时长。历史区间保留，维修和占用时间分别记录。

## 四、开发前的数据与技术准备

| 数据对象 | 必须能回答的问题 |
| --- | --- |
| 用户、角色、工位 | 谁执行了操作？操作人能管理哪些资料？工单在哪个工位执行？ |
| 夹具型号、型号与工位的适配关系、夹具实物 | 需要哪一类夹具？哪件实物适配？现在在哪里、处于什么状态？ |
| 工单、需求明细、分配明细 | 要多少件？实际选中了哪些编号？何时占用或撤销？ |
| 借还记录、维护记录、状态历史 | 谁领谁还？维修从何时开始、何时结束？历史闲置区间如何还原？ |

前端使用 Vue、HTML、CSS、JavaScript，后端使用 Java、Spring Boot、MyBatis，数据存储使用 MySQL。开发顺序建议为建模与样例数据、账号权限与台账、工单匹配与分配、领用归还与维修、历史查询与场景验收。先打通一张工单，再补齐各角色的管理页面。

## 五、可复用的演示和测试样例

以下为虚构样例。工单 WO-001 在 A 工位需要一件 M 型夹具。F-01、F-02、F-03 均为 M 型。F-01 适配 A 且空闲，F-02 适配 A 但维护中，F-03 空闲但仅适配 B。

| 场景 | 预期结果 |
| --- | --- |
| 为 WO-001 查询可用夹具 | 候选清单只有 F-01 |
| 两张工单同时确认 F-01 | 只有一张成功，另一张收到占用提示，数据库中仅有一条有效占用 |
| WO-001 改为需要两件，当前只有一件适配且空闲 | 提示缺一件，按整单分配建议规则，F-01 仍空闲 |
| 分配 F-01 后撤销，再分配并领用 | 撤销后恢复空闲；再次分配、领用后为已借出，保留两次分配历史 |
| F-01 损坏归还，随后修复 | 归还时直接进入维护中；修复后重新出现在候选清单，闲置从修复完成时起算 |
| 以 F-01 为条件查履历 | 可定位关联工单、领用人、借还时间、维修区间和历次闲置区间 |

## 六、开题前优先确认

1. **工单如何表达需求？** 建议工单直接填写型号、数量和工位。若要求由工件或工序推导夹具型号，需增加工艺与型号的对应关系及测试样例。
2. **谁负责分配和借还？** 建议工装管理员确认分配，操作员登记领用和归还。需确认是否要管理员复核、是否允许拆单或分批领用。
3. **闲置如何定义？** 建议从实物可用时起算，分配时截止。若学院或车间另有闲置天数阈值、统计口径，应提供一个例子核对。
4. **学校要交什么、何时交？** 收集本届任务书、开题模板、独立文档清单及开题、中期、论文初稿日期。开题报告再据此补充文献综述、研究方法、进度安排和预期成果。

确认前可先使用模拟工单绘制用例图、状态图及数据库概念模型。涉及真实车间的流程描述和参考文献须经材料核实。
